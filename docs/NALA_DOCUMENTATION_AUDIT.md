# Auditoría documental de NALA

**Corte:** 2026-09-28. **Corpus inventariado:** 204 archivos Markdown bajo `docs/` según `Get-ChildItem -Recurse`. La clasificación distingue estado de documento de estado de funcionalidad.

## Estados

- `ACTUALIZADO`: revisado contra fuente y corte actual para su alcance declarado; no implica producción.
- `PARCIAL`: útil pero faltan rutas/estados/approval o parte del contenido contradice la evidencia.
- `OBSOLETO`: una sección/version histórica ya no debe instruir ni representar estado actual.
- `DUPLICADO`: contenido/propósito se solapa con fuente canónica; mantener sólo navegación/historia hasta decidir archivo.
- `SIN EVIDENCIA`: no se validó el contenido de ese documento contra el código en esta ampliación. La ausencia de revisión no significa que el contenido sea falso.

## Contradicciones que requieren corrección antes de publicar comercialmente

1. “Familia ilimitada” en la tabla anterior de [PRICING_AND_PLANS](PRICING_AND_PLANS.md) contradijo `MaxPets=25` en migración y legacy fallback. Se corrigió en este corte; confirmar enforcement en cada ruta y base activa.
2. Tablas objetivo de `FEATURES.md` incluyen cuota/feature sin gate/migración demostrados.
3. `UserPlus`, `UserFamilia`, tiers B2B y `ProviderMembershipTier` son ejes distintos; no renombrarlos como un catálogo único sin migración/API.
4. Precios codificados/UI no equivalen a precio aprobado, publicado o cobrado. Existe un gate de approvals en el workflow de despliegue productivo; no se encontró bloqueo runtime de catálogo o compra por esas flags y los valores productivos no se consultaron.
5. Pago SINPE/manual, tarjeta/CyberSource y renovación no acreditan settlement ni checkout recurrente universal.
6. “AI” se refiere a matching visual condicionado, no a OpenAI/RAG/copiloto.
7. GPS API no acredita dispositivo/red; consulta clínica no acredita telemedicina audiovisual; certificados digitales no acreditan SENASA.
8. Store/Provider booking no acredita marketplace con stock, payout, comisión, refunds o disputas.
9. Multisede/Enterprise/SLA aparecen como necesidades o tiers parciales, no como contrato/servicio probado.
10. Modelos CR/LATAM y proyecciones no tienen datos de cohortes o invoices; no convertirlos en forecast aprobado.

## Decisión sobre contenido obsoleto

No se borraron documentos durante esta pasada: las propuestas fechadas y documentos de legal/deployment pueden conservar valor probatorio/histórico, y no hubo revisión completa para declarar obsolescencia de cada uno. Los duplicados se identifican como tales y deben redirigirse a fuente canónica antes de archivar. La limpieza de claims falsos se limita a los nuevos informes y debe aplicarse al copy específico tras revisión de propietario; no retirar condiciones de contrato, claims legales ni datos históricos sin aprobación.

## Alcance y limitaciones

Se inspeccionó el código de tiers/pricing/entitlement, migración relevante, controladores de suscripción, UI de tiers, Bicep, package frontend, documentación de negocio/pricing, arquitectura/capacidades, y sitios oficiales accesibles. No se inspeccionaron todos los 204 documentos línea por línea, DB/producción/proveedores, contrato/IVA con asesor, factura Azure, ni cada test de cada handler. No se debe llamar a esto auditoría documental completa de todo el corpus; es un registro con zonas de evidencia pendiente. Para la cobertura técnica general, ver [DOCUMENTATION_AUDIT existente](DOCUMENTATION_AUDIT.md), [plan de esta actualización](auditoria/DOCUMENTATION_UPDATE_PLAN.md) y [changelog](auditoria/DOCUMENTATION_CHANGELOG.md).
