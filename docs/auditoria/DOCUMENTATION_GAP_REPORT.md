## Revalidación de `FEATURES.md` §24 (2026-09-28)

- Los bullets de servicio central, migraciones y endpoint de snapshot estaban desactualizados como pendientes; existe modelo/seed de `PlanEntitlement`, servicio registrado y API snapshot. La evidencia está enlazada en [FEATURES](../FEATURES.md), sección 24.
- La definición configurable todavía es parcial: `PlanEntitlement` no tiene CRUD administrativo/API verificado, el administrador de planes solo edita nombre/descripción/precios y `EntitlementService` mantiene `FreeEntitlements()`/`GetLegacyEntitlement()` como fallback.
- `EntitlementMeter` y su hook existen, pero no hay call site en `frontend/src`; no se encontró alerta proactiva por proximidad al límite.
- Hay gates por dominios y pruebas unitarias de servicio/downgrade, pero no evidencia de enforcement completo para todas las claves ni de pruebas integradas completas de upgrade/downgrade. Los gates de API keys/certificados/pasaportes conservan reglas por tier/cuota local.
- El catálogo público se consume en componentes de suscripción, pero no demuestra aprobación comercial de precios. El [registro legal](../LEGAL_REVIEW_REGISTER.md) mantiene términos/privacidad y otras superficies en `draft`/`pending`.
- `dotnet test PawTrack.sln` pasó 1,803 pruebas (1,634 unitarias, 169 integración) en el corte; no acredita despliegue de migraciones ni disponibilidad de producción.
