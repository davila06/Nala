## CI, publicación y límites

- [infra.yml](../../.github/workflows/infra.yml) y [backend.yml](../../.github/workflows/backend.yml) refieren `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `AZURE_RESOURCE_GROUP`, `ACR_NAME`, `CONTAINER_APP_NAME`, `SQL_ADMIN_PASSWORD`, `SMOKE_API_URL` y `ALERT_EMAIL_ADDRESS` según paso; son **nombres de GitHub Secrets**, no evidencia de presencia. Los IDs de cliente/tenant/subscripción son identificadores, no contraseñas, aunque estén almacenados en GitHub Secrets. `azure/login@v2` requiere validar federación/OIDC y permisos del workflow.
- [frontend.yml](../../.github/workflows/frontend.yml) refiere `AZURE_STATIC_WEB_APPS_API_TOKEN` y `VITE_*`. Un valor `VITE_*` se publica en JS y no debe contener tokens privados. Hay credenciales de SQL **de prueba** en workflows versionados; no se reproducen aquí ni se equiparan a secretos productivos.
- [main.bicep](../../infra/main.bicep) asigna roles Key Vault Secrets/Crypto, Storage Blob Contributor, ACR Pull y administrador Entra de SQL; asignación declarada no acredita permiso efectivo en la cuenta. No se accedió a Key Vault ni al portal.

Ver [variables](ENVIRONMENT_VARIABLES_AUDIT.md), [matriz de gaps](MISSING_EXTERNAL_CONFIGURATION.md) y [reporte ejecutivo](EXTERNAL_SERVICES_EXECUTIVE_REPORT.md). No completar campos de un entorno con valores inventados.
