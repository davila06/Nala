## RBAC y secretos: declarar no es otorgar

- [main.bicep](../../infra/main.bicep) declara `Key Vault Secrets User`, `Key Vault Crypto User`, `Storage Blob Data Contributor`, `AcrPull` y administrador Entra de Azure SQL sobre la user-assigned identity de API/job. **Principal efectivo, propagación, grants de base y mínimo privilegio:** `NO_VERIFICADO`.
- [Program.cs](../../backend/src/PawTrack.API/Program.cs) necesita `Jwt:Key`; [StartupGuards.cs](../../backend/src/PawTrack.API/Middleware/StartupGuards.cs) no rechaza todas las referencias textuales de Key Vault. La API/job en Bicep no inyectan `Jwt__Key` ni `secretRef` correspondiente: validar override real **sin mostrar su valor** antes de publicar.
- [ExternalProviderConfigurationHealthCheck.cs](../../backend/src/PawTrack.API/HealthChecks/ExternalProviderConfigurationHealthCheck.cs) exige Storage ConnectionString mientras Blob admite ServiceUri; ese check tiene tag `external`, no `ready`. Más grave para despliegue: [backend.yml](../../.github/workflows/backend.yml) y [smoke-tests.yml](../../.github/workflows/smoke-tests.yml) consultan `/health/ready` sin JWT Admin.
