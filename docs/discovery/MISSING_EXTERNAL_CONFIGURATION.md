## Riesgo de referencia JWT no resuelta

**CRÍTICO condicionado a la configuración efectiva:** [appsettings.json](../../backend/src/PawTrack.API/appsettings.json) contiene referencias textuales `@Microsoft.KeyVault(...)`; [Program.cs](../../backend/src/PawTrack.API/Program.cs) consume `Jwt:Key` como string y [StartupGuards.cs](../../backend/src/PawTrack.API/Middleware/StartupGuards.cs) solo valida longitud y un conjunto fijo de valores débiles. [main.bicep](../../infra/main.bicep) inyecta URI del vault, pero no `Jwt__Key` ni `secretRef` JWT; no se encontró `AddAzureKeyVault` en API/Infrastructure. **Si no hay override externo**, la referencia pública podría utilizarse como clave HMAC. Hay que verificar la fuente efectiva sin revelar el valor, resolver Key Vault realmente y fallar ante placeholders. Runtime productivo `NO_VERIFICADO`.

También se encontraron contraseñas estáticas **de SQL de CI** versionadas en [backend.yml](../../.github/workflows/backend.yml), [e2e.yml](../../.github/workflows/e2e.yml) y [enterprise-quality.yml](../../.github/workflows/enterprise-quality.yml). No se reproducen ni se equiparan a credenciales productivas; sustituir por secretos de CI aislados y rotables. Los secretos de GitHub, user-secrets y vault no se consultaron.

**ALTO, gate externo manual:** [Test-ExternalProviderReadiness.ps1](../../scripts/Test-ExternalProviderReadiness.ps1) valida evidencia aprobada de Azure, WhatsApp, GPS, pagos y email sin leer credenciales, pero no se encontró invocación en los [workflows](../../.github/workflows/). Ejecutarlo/aprobarlo por entorno antes de activar proveedores; la presencia del script no verifica una aprobación. **MEDIO, widget por entorno:** [widget.ts](../../frontend/src/widget/widget.ts) usa URL API productiva fija; validar staging y distribución a clínicas sin apuntar a la API de otro entorno.
