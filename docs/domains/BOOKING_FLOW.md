# Reservas de servicios

El cliente consulta disponibilidad sin autenticación y crea reserva con JWT; el proveedor usa rol `ServiceProvider` para ver reservas entrantes; participantes pueden cambiar estado o reprogramar según [ProviderBookingsController](../../backend/src/PawTrack.API/Controllers/ProviderBookingsController.cs). Se almacenan [ProviderBookings y ProviderPayments](../../backend/src/PawTrack.Infrastructure/Persistence/PawTrackDbContext.cs), pero el registro de tablas no demuestra un cobro efectivo.

**Pagos y devoluciones:** la reserva de tarjeta cotiza `ProviderBooking.TotalCrc`, enlaza el pago a un `PaymentIntent` y espera settlement para confirmar y escribir ledger mediante [ChargeCardCommandHandler](../../backend/src/PawTrack.Application/Payments/Commands/ChargeCard/ChargeCardCommand.cs) y [PaymentIntentSettledDomainEventHandler](../../backend/src/PawTrack.Application/Payments/Events/PaymentIntentSettledDomainEventHandler.cs). `IPaymentGatewayService` registra `CyberSourcePaymentGatewayService`; no se verificó una transacción real en sandbox. Para SINPE, el cliente reporta y Admin confirma manualmente. Si la devolución SINPE ya se ejecutó fuera de PawTrack, Admin puede registrar importe incremental, referencia y motivo en [AdminServiceProvidersController](../../backend/src/PawTrack.API/Controllers/AdminServiceProvidersController.cs), mediante [RecordManualProviderRefundCommandHandler](../../backend/src/PawTrack.Application/ServiceProviders/ProviderPaymentCommands.cs). El registro crea una operación idempotente y auditoría; no transfiere fondos ni constituye evidencia bancaria independiente. Pagos con `PaymentIntent` se rechazan en esta ruta manual y deben usar el flujo de reembolso del gateway. El pago integral sigue `PARCIALMENTE_IMPLEMENTADO`.

**Validación de código:** pagos de reservas, settlement, cancelación, devolución externa y endpoint Admin pasaron 23/23 pruebas focales (`ChargeCardCommandHandlerTests`, `PaymentIntentSettledDomainEventHandlerTests`, `UpdateProviderBookingStatusCommandHandlerTests`, `ProviderPaymentCommandTests`, `RecordManualProviderRefundCommandTests`, `AdminServiceProvidersControllerTests`). `dotnet test PawTrack.sln --no-restore --verbosity minimal -p:BaseOutputPath=backend/test-out/` pasó 1922/1922. El gate de idempotencia ejecutó migración/upgrade y carrera concurrente en LocalDB desechable; esto no verifica transferencia SINPE real, sandbox CyberSource, aplicación a base persistente, staging o producción.

**Límites restantes:** [ManualProviderPaymentGateway](../../backend/src/PawTrack.Application/ServiceProviders/Payments/ManualProviderPaymentGateway.cs) crea un intento `Pending`, sin `ExternalIntentId`. La confirmación de disponibilidad concurrente y notificación de reserva siguen `NO_VERIFICADO` end-to-end.
