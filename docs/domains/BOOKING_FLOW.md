# Reservas de servicios

El cliente consulta disponibilidad sin autenticación y crea reserva con JWT; el proveedor usa rol `ServiceProvider` para ver reservas entrantes; participantes pueden cambiar estado o reprogramar según [ProviderBookingsController](../../backend/src/PawTrack.API/Controllers/ProviderBookingsController.cs). Se almacenan [ProviderBookings y ProviderPayments](../../backend/src/PawTrack.Infrastructure/Persistence/PawTrackDbContext.cs), pero el registro de tablas no demuestra un cobro efectivo.

**Pagos y devoluciones:** el cliente reporta SINPE y un Admin confirma el pago. Si la devolución SINPE ya se ejecutó fuera de PawTrack, Admin puede registrar el importe incremental, referencia y motivo en [AdminServiceProvidersController](../../backend/src/PawTrack.API/Controllers/AdminServiceProvidersController.cs), mediante [RecordManualProviderRefundCommandHandler](../../backend/src/PawTrack.Application/ServiceProviders/ProviderPaymentCommands.cs). El registro crea una operación idempotente y auditoría; no transfiere fondos ni constituye evidencia bancaria independiente. Pagos con `PaymentIntent` se rechazan en esta ruta manual y deben usar el flujo de reembolso del gateway. El pago integral sigue `PARCIALMENTE_IMPLEMENTADO`.

**Validación de código:** las pruebas de pagos y cancelación de reservas pasaron 12/12 con el filtro `ProviderPaymentCommandTests|UpdateProviderBookingStatusCommandHandlerTests`. Las pruebas específicas de devolución manual pasaron 3/3 con el filtro `RecordManualProviderRefundCommandTests`; cubren precisión a dos decimales, rechazo de tarjeta y replay/conflicto de idempotencia. Ambas ejecuciones usaron `dotnet test backend/tests/PawTrack.UnitTests --no-restore --filter "<filtro>" --verbosity minimal -p:BaseOutputPath=backend/test-out/`. Esto no verifica transferencias SINPE reales, gateway externo, base SQL aplicada ni producción.

**Límites restantes:** [ManualProviderPaymentGateway](../../backend/src/PawTrack.Application/ServiceProviders/Payments/ManualProviderPaymentGateway.cs) crea un intento `Pending`, sin `ExternalIntentId`. La confirmación de disponibilidad concurrente y notificación de reserva siguen `NO_VERIFICADO` end-to-end.
